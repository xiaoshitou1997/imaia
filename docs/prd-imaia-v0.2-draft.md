## 1. 背景与定位

个人真实对话分散在微信（生活）与飞书（工作），彼此孤立、格式互不兼容；AI 能力（自动
回复、记忆、定时任务、群画像）逐平台搭建则重复建设且无法共享上下文。

imaia = **智能聚合中枢 IM**：一个管理系统，把两个 IM 平台统一接入一套自有的会话模型，
AI 原生运行其上。对各平台而言 imaia 是一个连接方；对主人而言是查看、检索、指挥所有
对话与 AI 行为的唯一入口。控制台为主力管理面。

**v0.2 变更**：AI 只在微信/飞书内对话，控制台不提供任何 AI 对话入口。

## 2. 需求访谈结论（2026-11-13，本版依据）

| 域 | 结论 |
| --- | --- |
| 场景 | @机器人干活（查信息/生图/设提醒）、AI 代回复兜底、控制台统一收件箱+检索翻历史、统计报表群画像——全要 |
| 回复口径 | 群=被 @ 才回；私聊=线级开关开了就回；不主动插话 |
| 人设 | 按会话线配置不同人设（像群友/像秘书…），控制台编辑 |

| 记忆 | 仅 AI 自动沉淀，挂会话线；无手动录入、无全局层（推翻 v0.1 口径） |
| 洞察 | 三出口全要（控制台报表页/群内指令/周期落库）；谈资乐子+决策参考+年鉴留存全要 |
| AI 技能 | 生图、生视频、网页搜索；语音 TTS/ASR 砍出 v1 |
| 护栏 | 线级开关+群 @ 门控+幂等防重发+静默时段；不要频控、不要随机延迟 |

| 控制台 | 纯管理面；无「与 AI 对话」面板（推翻 v0.1 决策 13） |

## 3. 目标

- G1 **统一接入**：微信、飞书接入后全部会话消息以一套统一模型归档与呈现；新增平台仅
  需新增一个适配器实现。
- G2 **AI 原生**：接入的会话自动获得 AI 能力（自动回复、记忆、定时任务、群画像、生成
  媒体与搜索）。
- G3 **可管理**：人设、开关、任务、记忆、模型、接入全部经控制台查看与调整，敏感信息
  不出系统。
- G4 **行为克制**：自动化默认关闭、显式开启；被 @ 门控、幂等防重发、静默时段兜底。

## 4. 非目标（v1 明确不做）

- 多用户/多租户、公网部署（仅绑定本机回环）。
- 知识库（文档问答/RAG）。
- 跨线桥接（一条 AI 上下文同时服务多条线）——**不做，数据模型也不预留**。
- 重开对话（上下文清零重来）——不做。
- 语音能力：TTS 语音回复、ASR 语音转写（v2 再评估；语音消息在 v1 只归档不回复）。
- 飞书群全量归档（敏感权限 `im:message.group_msg`；默认仅 @ 机器人消息入档）。
- 飞书原生音频气泡、微信官方 app 形态接入（抽象预留）。
- 控制台 AI 对话面板/内置对话线。

## 5. 用户与角色

| 角色 | 说明 |
| --- | --- |
| hub 主人 | 唯一用户，兼管理员与使用者：配置接入、编辑人设与开关、管理任务、看报表 |
| IM 联系人与群成员 | 外部消息来源，非系统用户；消息按平台投递规则进入归档 |
| AI 助理 | 系统内行为者：在开启的会话中回复、执行技能、沉淀记忆、执行定时任务 |

## 6. 范围

### 6.1 In Scope（v1）

- 微信（agent-wechat daemon）与飞书（自建应用，WS 长连接）接入与归档；接入实例
  结构化存储、同平台多实例。
- 统一会话模型：会话线、不可变消息档案（保留平台原始报文）、幂等投递。
- AI 自动回复：多模态输入理解（文本、图片视觉理解、视频/表情包封面理解；语音消息
  只归档）、按线人设、意图即工具（提醒/记忆/搜索/生图/生视频）。
- 记忆：AI 自动沉淀，挂会话线，本线后续对话可见。
- 任务自动化：一次性提醒、cron 周期任务、周期报告生成；对话式创建 + 控制台管理。
- 技能：生图、生视频、网页搜索。
- 会话洞察：统计/评析/年鉴三出口（控制台报表页、群内指令、周期落库）。
- 护栏：线级自动回复开关（默认关）+ 全局总开关 + 群 @ 门控 + 幂等防重发 + 静默时段。
- WebUI 管理闭环（页面清单实现轮定稿），与控制台 API 同源部署。

### 6.2 Out of Scope

见 §4。

## 7. 需求

### 7.1 统一接入

- REQ-001 以「接入实例」为单元配置 IM 接入：平台、名称、启用状态、结构化配置（含平台
  凭据）；同平台允许多实例并存。
- REQ-002 接入配置为系统内数据，不依赖环境变量；修改后重启生效。
- REQ-003 每个已启用实例由对应平台适配器独立驱动（连接、重连、进度、媒体、发送）；
  核心流程不感知平台差异。
- REQ-004 未配置/未启用的实例不影响其他平台运行。
- REQ-005 消息投递至少一次语义，处理器幂等；重复投递不得产生重复归档或重复回复。
- REQ-006 连续处理失败达阈值终止该平台事件流；网关瞬态故障单独计数。

### 7.2 会话与归档

- REQ-010 每个平台原生聊天通道对应一条会话线：平台原生会话标识、展示名、类型
  （私聊/群聊）、线级人设、自动回复开关、最近活跃；首条消息到达自动登记。
- REQ-011 收到的消息全量归档，保留原始平台报文；按（接入实例, 平台消息 id）去重。
- REQ-012 归档保留平台原生消息类别与 @ 提及标记；每条消息记录来源 origin（human/ai），
  微信侧由系统写入区分 AI 与主人。
- REQ-013 群会话维护成员快照（成员标识、展示名、最近活跃），供画像与统计使用。
- REQ-014 飞书群默认仅归档 @ 机器人消息。

### 7.3 AI 回复

- REQ-030 自动回复双开关：线级开关（默认关，会话列表随手切换）+ 全局总开关；关闭的
  会话只归档永不回复。
- REQ-031 触发口径：群消息必须真 @ 机器人才触发；私聊开关开启即回；不主动插话。
- REQ-032 护栏：静默时段（默认 00:00–07:00 不回复，可调）；所有发送动作携带幂等标识，
  事件重放不重复发送。
- REQ-033 多模态输入：文本直进模型；图片走视觉模型；视频与表情包以封面/预览理解；
  语音消息只归档不触发回复。
- REQ-034 人设按会话线配置（im 线上直接设置，控制台编辑，即时生效）；命中该线人设即
  用；系统机制说明由系统注入，不受人设覆盖。人设只有一个概念，不分级不回落
  （v0.2 变更：废除四级回落）。
- REQ-035 记忆：模型在对话中自主沉淀记忆，挂会话线；该线后续对话自动注入；控制台可
  查看与删除。
- REQ-036 技能经原生工具调用执行（无文本标记协议，v0.2 变更）：生图/生视频产物上传
  来源平台发送并登记产物档案；网页搜索回答时效性问题。
- REQ-037 输出降级：生成失败按业务静默并记日志，不阻塞消息流。

### 7.4 任务自动化

- REQ-040 三类任务：一次性提醒（到点在指定会话发送指定内容）、cron 周期任务（按计划
  由 AI 措辞或发送固定内容）、周期报告（按周期对会话线生成洞察报告）。
- REQ-041 对话式创建：主人在 IM 里自然语言下单（「明早 8 点提醒我…」），模型落为结构
  化任务并回执确认；控制台提供同等的新建/编辑/启停/删除。
- REQ-042 任务执行按设定时间发送，**不受静默时段限制**（主人意志优先；静默时段只约束
  被动自动回复——v0.2 决策）；幂等键由任务 id+触发时间派生；一次性任务失败标记失败，
  不无限重试。

### 7.5 会话洞察

- REQ-060 统计类：成员消息条数与字数、活跃度排行、表情消息计数、回复时延、@提及与
  被 @ 回复率，支持任意时间区间聚合。
- REQ-061 评析类：成员幽默度评析、口头禅提取、话题分类与热度、成员画像（性格/兴趣/
  互动风格）。
- REQ-062 年鉴类：月报、年度总结。
- REQ-063 三出口：控制台报表页随时查看；群内指令（「@机器人 本周统计」）报告直接发
  回群里；周期报告定时生成落库，控制台回看历史。
- REQ-064 报告落库按（会话线 × 周期类型 × 周期起点）唯一。

### 7.6 控制台与管理

- REQ-050 WebUI 是完整的后台管理系统：覆盖接入实例、会话与消息（统一收件箱+全文
  检索）、记忆、任务、模型目录、人设与开关、洞察报表；每个资源一致的列表/筛选/详情/
  新建/编辑/删除/启停操作与统一交互（分页、空态、加载与错误反馈、危险操作二次确认、
  表单校验）。
- REQ-051 人设、开关、记忆、任务、模型目录修改即时生效；接入配置修改重启生效。
- REQ-052 控制台仅绑定本机回环地址；接入凭据任何响应只以掩码出现，日志无凭据明文；
  掩码值提交时还原为原值。
- REQ-053 控制台不提供与 AI 的对话入口（v0.2 决策）；AI 交互只发生在微信/飞书内。
- REQ-054 接入实例生命周期：新建、编辑、启停、删除（已有会话数据的实例禁止删除并
  提示）；配置编辑提示重启生效。

## 8. 关键流程

1. **被动回复**：平台消息 → 归档（去重）→ 开关/@ 门控/静默时段校验 → 多模态组包 →
   模型推理（含工具）→ 发送回复与生成媒体 → 记忆/任务落库 → 记录已处理。任一步失败
   事件重放，幂等门吸收重复。
2. **任务**：IM 下单或控制台创建 → 到点执行发送 → 状态更新；周期任务按 cron 重复。
3. **报表**：周期定时生成落库；群内指令即时生成发送；控制台随时按区间出数。
